# 游戏接入指南

从一个空文件夹到你的游戏出现在大厅里，只需三步。架构背景见 [[技术框架定稿]]。

## 三步接入

1. **复制起点**：把 `games/whale-run/` 复制为 `games/<你的id>/`（id 用小写字母、数字、连字符，如 `zombie-whale`）
2. **开发你的游戏**：任意技术，产物必须是纯静态文件、入口 `index.html`，并满足下述协议契约
3. **登记**：在根目录 `games.json` 加一行，提 PR（只动你自己的文件夹 + games.json）

## 硬性要求（协议契约）

| 要求 | 说明 |
| --- | --- |
| 纯静态产物 | 入口 `games/<id>/index.html` 直接可跑，无后端、无必须的构建步骤（用 Vite 等构建的，把产物提交进文件夹） |
| 引入协议壳 | `<script src="/shared/js/bluefish-shell.js"></script>`（绝对路径，从仓库根起服务时生效） |
| 生命周期上报 | 加载完成调 `BFShell.ready()`；每局结束必须调 `BFShell.gameOver({score})`（大厅靠它记最高分） |
| 分数上报 | 游戏中调 `BFShell.score(n)`，节流至 ≤1 次/秒 |
| 响应暂停 | 注册 `BFShell.onPause` / `BFShell.onResume`，暂停时停游戏逻辑（壳已自动接好失焦暂停，你只需响应回调） |
| 分辨率自适应 | 设计分辨率自定，manifest 声明 `aspect`；canvas 用 `BFShell.fitCanvas()` 等比缩放填满 |
| 禁用阻塞弹窗 | 不用 `alert` / `confirm` / `prompt`，结束画面自己画 |
| 资源归属 | 资源自包含在自己文件夹；统一形象素材从 `/shared/assets/` 引用（素材包待产出，先用自绘占位） |
| 可独立游玩 | 直接打开 `/games/<id>/` 不进大厅也能玩（shell 在非 iframe 环境自动降级 no-op） |

## games.json 字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | string | ✔ | 唯一标识，即文件夹名 |
| title | string | ✔ | 大厅卡片显示名 |
| author | string | ✔ | 作者（署名/花名） |
| type | string | ✔ | `fighting` / `platform` / `td` / `runner` / `other` |
| entry | string | ✔ | 相对仓库根的入口路径，如 `games/zombie-whale/index.html` |
| thumb | string |  | 缩略图路径，建议 480×270 PNG；缺省显示渐变占位卡 |
| aspect | string |  | 画面比例，默认 `16:9` |
| description | string | ✔ | 一句话介绍 |
| controls | string | ✔ | 操作说明（大厅不强制展示，便于文档化） |
| order | number |  | 卡片排序，越小越靠前 |

## 通信协议

消息信封：`{ src: 'bf-game' | 'bf-hub', type: string, ...payload }`，经 `postMessage(msg, '*')` 传递（同源场景，v1 从简）。**不要自己手写 postMessage，用 BFShell。**

**游戏 → 大厅**（由 BFShell 方法发出）：

| type | 载荷 | 时机 |
| --- | --- | --- |
| ready | — | 加载完成、可交互 |
| score | `score: number` | 分数变化（≤1次/秒） |
| gameover | `score: number, win?: boolean` | 单局结束（每局都要发） |
| exit | — | 请求返回大厅（游戏内"退出"按钮） |

**大厅 → 游戏**（由 BFShell 回调接收）：

| type | 作用 |
| --- | --- |
| pause | 立即暂停（大厅暂停按钮 / 切走标签页自动触发） |
| resume | 恢复 |

## BFShell API

| API | 说明 |
| --- | --- |
| `BFShell.inHub` | 是否运行在大厅 iframe 里（false = 独立运行） |
| `BFShell.ready()` | 上报就绪 |
| `BFShell.score(n)` | 上报当前分 |
| `BFShell.gameOver({score, win})` | 上报单局结束 |
| `BFShell.exit()` | 请求返回大厅 |
| `BFShell.onPause(cb)` / `BFShell.onResume(cb)` | 注册暂停/恢复回调，可多个；失焦（visibilitychange）时壳自动触发 pause 回调 |
| `BFShell.bestScore` | 大厅注入的历史最高分（number 或 null），可用于结束画面展示 |
| `BFShell.fitCanvas(canvas, w, h)` | 设计分辨率 canvas 等比缩放填满窗口（letterbox 居中、自适应 resize） |

最小示例：

```html
<script src="/shared/js/bluefish-shell.js"></script>
<script>
  const canvas = document.getElementById('game');
  BFShell.fitCanvas(canvas, 960, 540);
  BFShell.ready();
  BFShell.onPause(() => paused = true);
  BFShell.onResume(() => paused = false);
  // 每秒：BFShell.score(sec)
  // 单局结束：BFShell.gameOver({ score: sec })
  // 退出按钮：BFShell.exit()
</script>
```

## 技术选型建议

- **默认推荐 Phaser 3**：格斗/闯关/塔防/跑酷全覆盖，教程最多，CDN 引入零构建即可开发：
  `<script src="https://cdn.jsdelivr.net/npm/phaser@3/dist/phaser.min.js"></script>`
  （jsdelivr 国内一般可达；担心不稳可下载 phaser.min.js 放进自己文件夹引本地）
- 轻量偏好：PixiJS / 原生 canvas（参考示例游戏 whale-run 就是纯 canvas）
- 允许任何能产出静态网页的引擎（含 Godot Web 导出；注意 wasm 包体较大、多线程导出在静态托管上有限制，请先小试）
- TypeScript 可选不强制；若用 Vite 等构建，产物必须提交到游戏文件夹内，保证 `index.html` 直接可用

## 自测清单（合并前必须全过）

- [ ] 从仓库根起静态服务，直接打开 `/games/<id>/` 可独立游玩
- [ ] 大厅里点开可玩；Esc / 关闭按钮可退出返回
- [ ] 大厅标题栏分数 HUD 实时变化；结束后卡片"历史最高"已更新
- [ ] 切走浏览器标签页，游戏自动暂停；大厅"暂停"按钮生效
- [ ] 游戏内退出按钮能返回大厅
- [ ] 无 `alert`/`confirm`；控制台无报错

## 提交流程

- 建分支 → 开发 → 自测清单全过 → PR（改动只含自己文件夹 + games.json 一行）
- games.json 合并冲突：保留双方条目即可（按 id 去重）
- thumb 可选；没有就先不填，占位卡不难看

## 常见坑

- **不要 file:// 直接双击打开**——fetch 与绝对路径全失效。务必从仓库根起静态服务：`npx serve .` 或 `F:/dev/anaconda/python.exe -m http.server 8000`
- **iframe 里手柄/指针锁定失效**——需要 `allow` 属性，大厅已配好；独立开发时无 iframe 不受影响
- **浏览器音频自动播放限制**——首次用户交互（点击/按键）之后再出声；开始画面先要一次输入即可
- **postMessage 用 `'*'` 目标**——同源场景无风险，v1 从简，勿自行改成域名判断引入 bug
- **构建产物忘提交**——本地构建跑得欢，部署后 404；PR 前从仓库根重新起服务完整过一遍自测清单
